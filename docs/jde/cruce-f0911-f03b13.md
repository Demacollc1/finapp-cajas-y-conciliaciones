# Cruce F0911 (conciliación bancaria) ↔ F03B13 (recepción de cheques)

Campos que permiten **vincular** una línea de la conciliación bancaria (`F0911`,
movimiento del banco) con el cheque/efecto que la originó (`F03B13`).

Ejemplo real (cheque **cobrado**, estado `0`): documento **RC 222998**, batch
**2940597**, banco **AUSTRO**, importe **112.11**, cliente **18145** (Proveedora
Industrial Ferretería Ramírez).

## Llaves de vinculación (de más a menos precisa)

### 1. Documento RC — vínculo exacto 1:1 ★
| | `F0911` (conciliación) | `F03B13` (recepción) |
|---|---|---|
| Tipo doc | `Tp doc` = **RC** | `A/D tipo doc` = **RC** |
| Compañía | `Cía doc` = **00001** | `A/D cía doc` = **00001** |
| Nº documento | `Número documento` = **222998** | `A/D nº doc` = **222998** |

> Además en `F0911`: `Referencia 2` = `00222998` y `Número pago` = `00222998`
> (el mismo documento, con ceros a la izquierda).

**Es la llave más precisa**: identifica la transacción individual en ambos lados.

### 2. Número de batch — agrupador contable ★
| `F0911` | `F03B13` |
|---|---|
| `Número batch` = **2940597** | `Número batch` = **2940597** |
| `Referencia 1` = **02940597** | `Tipo batch` = **DB** |
| `Tipo batch` = **DB** | |

> `F0911.Referencia 1` lleva el **nº de batch** — confirma que el batch es el
> agrupador natural del depósito (la decisión de vinculación bancaria).

### 3. Cuenta bancaria — segmentación por banco
| `F0911` | `F03B13` |
|---|---|
| `ID cuenta` = **00000059** | `Cuenta bcria LM` = **00000059** |
| `Número cuenta` = **1.110102.03** | |

### 4. Campos de apoyo (validación, no únicos)
| Concepto | `F0911` | `F03B13` |
|---|---|---|
| Cliente | `Nº direc` = 18145 | `Nº direc` / `Nº ppal` = 18145 |
| Importe | `Importe` = 112.11 | `Importe cheque` = 112.11 |
| Banco (observación) | `Explicación` = AUSTRO | `Explicación` = AUSTRO |
| Fecha contable | `Fecha LM` = 22/07/26 | `Fecha LM` = 22/07/26 |
| Moneda / período | USD · siglo 20 · AF 26 | USD · siglo 20 · AF 26 |

## Recomendación

- **Vínculo exacto (1:1):** usar el **documento RC** =
  `Tp doc + Cía doc + Número documento` ↔ `A/D tipo doc + A/D cía doc + A/D nº doc`.
- **Vínculo agregado (depósito / batch):** usar el **`Número batch`** (presente en
  ambas tablas, y también en `F0911.Referencia 1`).
- Los campos de referencia de `F0911` están **diseñados para llevar estas
  llaves**: `Referencia 1` = batch, `Referencia 2` / `Número pago` = documento.

## Qué confirma este registro (preguntas del paso 4)

- **Programa de confirmación de cobro:** `ID programa` = **`R03B680`** ✔
- **Estado cobrado:** `E E` = **`0`** ✔
- **Cuenta del banco:** `1.110102.03` (`ID cuenta 00000059`) es la cuenta de la
  conciliación bancaria — la misma que aparece en el detalle de la remesa.
- El registro trae también su **`Registro efectos` (DREG)** = `294058200001`.

## ⚠️ F0911R trae el batch de COBRO, no el de ENVÍO

Al revisar la tabla completa **`F0911R`** (Account Ledger Reconciliation) de una
transacción, el **batch de envío al banco (`2940589`) NO aparece** en ningún
campo. El batch que sí trae es **`2940597`**, que es el del **cobro/depósito**:

| | Valor en `F0911R` | Qué es |
|---|---|---|
| `Número batch` | **`2940597`** | Batch del **cobro** (asiento de banco) |
| `Referencia 1` | `02940597` | = el mismo batch de cobro |
| `Tp doc` + `Número documento` | `RC` + `222998` | Documento del cobro |
| `ID programa` | `R09130` | Programa de conciliación/refresco |
| Cuenta | `1.110102.03` (`ID cuenta 00000059`) | Cuenta del banco |

Hay **dos batches distintos** en el ciclo:

| Batch | Momento | Programa | ¿En `F0911R`? |
|-------|---------|----------|:-------------:|
| **`2940589`** | **Envío / remesa** al banco (depósito físico) | `R03B672` | ❌ No |
| **`2940597`** | **Cobro / conciliación** (asiento de banco) | `R03B680` → `R09130` | ✅ Sí |

### ¿Se puede agrupar la conciliación por el batch de envío (`2940589`)?

**No directamente en `F0911R`**, porque ese número no existe en la tabla. En
`F0911R` se puede agrupar por:
- **`Número batch` = `2940597`** (batch del cobro), o
- **Documento RC `222998`** (para el detalle 1:1).

**A validar:** ¿todos los cheques enviados juntos en el batch `2940589` se cobran
en el **mismo** batch `2940597`?
- Si **sí** → agrupar `F0911R` por `2940597` reconstruye el grupo del depósito.
- Si **no** (cada cheque genera su propio batch de cobro) → no hay una sola llave
  de batch en `F0911R` para el grupo; habría que reconstruirlo cruzando el
  **documento RC → `F03B13` → registro de efectos / batch de envío**.

> Para confirmarlo se necesita ver **varias líneas** de `F0911R` del mismo envío
> (aquí solo hay una: RC `222998`, 112.11).

## Relación con la conciliación externa (extracto del banco)

`F0911` es la conciliación **interna** de JDE (asientos contra la cuenta de banco
`1.110102.03`). Para el cruce contra el **extracto real del banco**:

- El **documento RC** y el **batch** enlazan el movimiento de banco con los
  cheques de `F03B13`.
- El **nº de transacción del banco** que captura FinancePro (ver
  [vinculacion-bancaria.md](vinculacion-bancaria.md)) es la llave hacia el
  **extracto externo**; el batch/RC son la llave hacia **JDE**.
